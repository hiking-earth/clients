# 路线发现与更新

独立 ODbL 数据集：`shared/data/catalog/osm.json`，保留 © OpenStreetMap contributors 和 https://www.openstreetmap.org/copyright。人工维护数据与 OSM 快照分开保存。OSM 标识去重，显示层标准化名称去重；不同来源同名可能合并，后续统一测试检查。

`python3 scripts/update-route-catalog.py` 默认覆盖中国、欧洲、北美、日本、大洋洲、南美、非洲、南亚的矩形区域，每区域最多1000条有名称的 hiking/foot 关系。不是全球全部路线；截断与区域重叠可能影响覆盖。只抓取发现档案，不拼接可能断裂的关系成员作为导航轨迹。

稳定关系 ID 更新同一路线；区域失败保留旧记录；全失败不覆盖文件；原子替换。源记录暂时消失不自动删除，避免数据源短时故障误删。每条保留采集时间、来源原值和待核验状态。采集时间不等于官方开放核验时间。

GitHub Actions 每6小时更新，workflow_dispatch 支持手动触发。定时任务只有合入默认分支后才生效；当前开发分支新增文件不表示已开启后台更新。公共 API 三次重试、请求超时和响应体大小限制。此阶段没有执行应用测试或构建。

全端客户端服务 `app/src/services/route-catalog.ts` 使用响应式目录；启动/回到前台最多每6小时获取一次 HTTPS 最新快照，保留上次缓存作为离线回退。`VITE_ROUTE_CATALOG_URL` 可以改为自有 CDN；默认 GitHub raw main。微信小程序需由账号所有者把快照服务域名加入 request 合法域名，建议生产使用自有 HTTPS 域名。后台抓取定时更新，前台刷新跟随快照；不是官方路况秒级实时服务。

第二个独立数据源为 USDA Forest Service 官方 National Forest System Trails 图层。`scripts/update-usfs-catalog.py` 分页获取前5000个符合查询条件的源路段，按 trail_cn 合并为路线发现档案，保存源单位和徒步用途属性；不把源路段长度冒充完整路线长度。不与 ODbL 快照混用许可。任何分页失败三次则保留前一次完整快照。

客户端和网页列表采用50条递增加载。网页地图按视野最多显示400个路线标记，完整档案仍可搜索；尚未性能验收。
